# 📋 IndustryLab — Matriz de Cumplimiento Técnico IEC 62443

Este documento detalla el alineamiento de IndustryLab con las normas **IEC 62443-3-3** (Requisitos de seguridad del sistema y niveles de seguridad) e **IEC 62443-4-2** (Requisitos técnicos para componentes IACS).

| Requisito Fundamental (FR) | Descripción IEC 62443-3-3 | Implementación en IndustryLab | Evidencia / Código |
|---|---|---|---|
| **FR 1: Control de Identificación y Autenticación (IAC)** | Identificar y autenticar a todos los usuarios, procesos y dispositivos antes de permitir el acceso. | Bastion SSH en DMZ (`dmz_jump`), lista de IPs autorizadas en Proxy DPI para funciones de escritura. | `network/modbus_dpi_filter.py` (`authorized_write_ips`), `network/docker-compose.yml` |
| **FR 2: Control de Uso (UC)** | Imponer privilegios asignados para impedir la ejecución no autorizada de comandos críticos. | Filtrado de Códigos de Función Modbus (permite FC 01-04 lectura a todos; restringe FC 05, 06, 15, 16 a EWS). | `network/modbus_dpi_filter.py` (`inspect_request`) |
| **FR 3: Integridad del Sistema (SI)** | Proteger la integridad de las aplicaciones de control y detectar anomalías en la lógica del proceso. | Enclavamientos de seguridad en Structured Text (`TRIP_INTERLOCK_ACT`, `EMERGENCY_TRIP_RST`), detección de pérdida de visión. | `plc/st_programs/industrial_cooling.st`, `scada/historian_service.py` |
| **FR 4: Confidencialidad de Datos (DC)** | Proteger la confidencialidad de la información transmitida en conductos de comunicación. | Tráfico corporativo aislado mediante túneles y pasarelas de salto; segmentación física/lógica de conductos. | `network/firewall_rules.sh` (Conduits C-01 a C-05) |
| **FR 5: Flujo de Datos Restringido (RDF)** | Segmentar la red en zonas lógicas y conductos para restringir comunicaciones innecesarias. | Implementación estricta del Modelo Purdue (Niveles 4/5, 3.5, 3, 0-2). Política por defecto `FORWARD DROP`. Prohibición IT->OT. | `network/firewall_rules.sh`, `network/kathara/lab.conf`, `config/purdue_model.yaml` |
| **FR 6: Respuesta Oportuna a Eventos (TRE)** | Registrar eventos relevantes para la seguridad y generar alertas ante comportamientos anómalos. | Pipeline de alarmas en tiempo real en SCADA Historian (`COOLING_HIGH_TEMP`, `LOSS_OF_VIEW`), reglas de detección IDS Snort/Suricata. | `scada/historian_service.py`, `network/ids_snort_rules.rules`, `logs/cascading_events.csv` |
| **FR 7: Disponibilidad de Recursos (RA)** | Proteger los sistemas contra condiciones de denegación de servicio para asegurar la continuidad operacional. | Protección contra inundación DoS en el proxy DPI, watchdog de pérdida de visión (Fail-Safe Trip a 95°C). | `network/modbus_dpi_filter.py`, `attacker/attack_dos.py`, `physical/icssim/plant_cooling.py` |
